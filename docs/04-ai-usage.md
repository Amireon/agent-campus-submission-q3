# AI 使用说明与个人交接

## 实际情况

本仓库第 3 题由 **AI（DeepSeek Harness）** 在 2026-10-28 的一轮会话中实现。AI 完成的范围包括：

- 需求拆解、文档语料设计（冲突、旧版、草稿、资料外主题）；
- 检索器、工具、Agent 循环、DeepSeek 原生工具调用适配、离线 Mock、CLI、演示器；
- 29 项自动测试、9 组模拟运行、9 组真实 DeepSeek 运行；
- README、五份文档、Trace 与失败记录。

业务 Agent 的 live 决策由 **DeepSeek Flash（`deepseek-flash`）** 生成；AI 编程助手负责代码与文档，两者不是同一层。没有采集模型内部思维过程，Trace 中只记录可公开的 `reason`、工具参数、观察摘要和 provider 元数据。

## AI 迭代与失败记录

以下是 AI 在实现中真实发生的调整，供评审核对，不冒充个人贡献：

1. **首次真实冲突运行失败**：14:47 的运行在第 2 步返回 `INVALID_MODEL_RESPONSE`，以 `incomplete/model_error` 结束。把 `max_tokens` 从 1200 提高到 2000 后重跑通过。失败 Trace 保留在 `examples/failures/initial-live/conflict/`。
2. **冲突信号误报**：早期版本把所有同标题数值差异都作为信号，导致“产品退款期限”也提示 D01/D02 的报销冲突。修复为只统计与本次查询有章节重叠的信号。
3. **追问检索误命中**：Mock 最初用 assistant 消息里的“报销”扩展查询，导致追问命中报销文档；改为只使用 user 消息中的关键词。
4. **数字校验过严**：模型提到草稿编号 `D09` 或旧版日期 `2025`/`7 天` 时被 `UNSUPPORTED_NUMBER` 拒绝。保留严格校验，让模型删去未引用数字；同时对 `01`/`1` 做归一化，避免日期误杀。
5. **演示断言过严**：live 模型先改写再检索（只检索一次）也被判失败；改为接受“首次查询已改写”或“多次检索中发生改写”。
